Portfolio Website

An early version of my personal site built from scratch using only HTML, CSS, and JavaScript — no frameworks, just clean and lightweight code.

Why build a Portfolio Website?

Creating a personal portfolio website is both a way to showcase my work and a chance to refine my technical and design skills.

It allows me to present to potential recruiters:

The skills and experience I’ve developed throughout my career

My personal web development projects, including the technologies I use and my overall approach to design and problem-solving

My working style, organization, and attention to detail through both the code and the user experience

Beyond showcasing my work, building this site was also an opportunity to apply and deepen my knowledge of modern web development — from semantic HTML and responsive CSS layouts to animations, and accessibility. I view this website as a living project: something I can continuously improve as I grow as a developer and designer.

Web Design

Design Tools

I explored UI/UX design using Figma, which helped me grasp the fundamentals of sketching and planning an application before development. I mainly used it to create an overall layout and visual direction for my projects.

Building my portfolio website was also an opportunity to dive deeper into web design principles, focusing on typography, color schemes, and visual balance.

In the end, I chose a clean and minimal design, with a simple typography and a color palette that reflects my personal taste and design preferences.

Architecture

Pre-compiling with SASS/SCSS

I used my personal website as an opportunity to practise and consolidate my knowledge of SASS. After some research, I decided to follow the 7-1 architecture pattern, which I adapted and simplified into five main folders to suit the scale of my project:

Abstracts: variables (color, font, margin, padding, etc), helper functions and mixins
Base: global styles such as typography, body and HTML defaults, animations, and utilities
Components: reusable elements like buttons, general cards, and project cards
Layouts: structure-related styles for the navbar, header, footer, and grid system
Pages: page-specific styles for eac of the five main sections (Home, Portfolio, About, Blog, and Contact)

Custom HTML Elements

I also created my own custom HTML element classes for the header, footer, and portfolio cards to improve readability and modularity in the codebase.

Lessons Learned

Throughout the development of this site, I performed several rounds of refactoring to improve both the structure and maintainability of the code.

Reworking the overall architecture gave me valuable insight into clean code principles and the importance of the DRY concept — lessons I will continue to apply in future projects.

One area I identified for further improvement is the consistency of the grid system across the entire site. Achieving a uniform layout structure remains one of my next challenges.

Looking ahead, I plan to build a new version of my portfolio website using more modern technologies such as React, Next.js, and Tailwind CSS. This will allow me to create a more dynamic, scalable, and visually consistent website while deepening my knowledge of these industry-standard tools.
