Linguappo

A simple, interactive app to make language learning easier.

Add your own vocabulary, practice with flashcards, and track your progress over time.

Motives for developing a Language App

As a language enthusiast, I often collected new words while reading or speaking with others. I jotted them down on random papers, but soon realized it was hard to stay organized. This inspired me to create an app that makes vocabulary learning simple, structured, and motivating.

Linguappo was born as a personal project to keep my vocabulary organized and accessible anywhere. It lets me quickly review new words from my phone or computer, even while commuting. The goal was to create a simple tool that encourages regular practice and makes vocabulary management effortless.

I first explored this idea a few years ago with a small Android app in Java. It eventually grew into Linguappo, a full web application with responsive design, database integration, and user authentication — my first complete front- and back-end web project.

How it works

Sign-up and Dashboard

Users first sign up and create an account, with their information stored in a MongoDB database. Once logged in, they land on the main dashboard, where they can:

Create new projects for a specific language and theme

Manage and visualize project data: track total and incomplete vocabulary, and view chronological entries in graphical form

Complete missing translations directly within the dashboard

Vocabulary and Tags

For each project, users can save their own items:

Add entries — input a word, expression, verb, etc., along with its translation (immediately or later)

Organize with tags — create as many tags as needed, e.g., “Adjective”, “Verb”, “Expression”, “Slang”

Manage tags — edit or delete tags, with automatic updates to the database

Game

The core feature of the app allows users to:

Filter items by various criteria: tags, number of entries, sampling method, or knowledge evaluation

Play the Flipping Card game in either language direction, validate their knowledge (pass or fail), and receive a final score

Manage items by deleting them or updating their details, including vocabulary, translation, tags, and knowledge evaluation

Dictionary

Users can search for items within a project:

Find a word or expression and get its translation, or search by translation to find the original vocabulary

Architecture

MVC(S) Pattern

In the first version of my application, I implemented an MVC (Model-View-Controller) architecture. Later, I refactored it to introduce Services, making functions reusable across different controllers.

Models

The data access layer has 4 models: User, Project, Vocabulary, and Tag. Each interacts with MongoDB, performing queries to retrieve, save, or update data.

Views

Pages and modals are built as EJS templates, with partials for reusable components like the header, footer, and navbar.

Controllers

They use Service classes directly, eliminating the need to rewrite functions across different controllers and adhering to the DRY principle.

Services

They contain the business logic and act as a layer between controllers and models. Each model has a corresponding service.

Frontend

During refactoring, I used controller closures to separate the user interface from the logic:

The game logic closure handles functions like storing data and calculating results

The game UI closure manages DOM elements, performing actions such as flipping cards and showing or hiding icons


I also used AJAX calls to update specific elements without reloading the entire page.

Lessons Learned

The application still has areas that could benefit from further refactoring.

Since the design wasn’t fully planned in advance, there are inconsistencies in typography and color scheme, and the CSS could be improved by using a preprocessor.

Refactoring the architecture gave me valuable insights into clean code and the DRY principle, which I plan to apply in future projects.

A future challenge would be to build a similar app using React for the front-end and UI frameworks for a more structured interface.
