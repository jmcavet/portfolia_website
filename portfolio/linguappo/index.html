Linguappo

An application to learn a new language in a friendly way.

Enter your own vocabulary, train yourself with flipping cards, and review your score and progress.

Motives for developing a Language App

Being a lover of foreign languages, I am always keen on learning new ones. Usually, I would read newspapers or books, chat with people, which is certainly the most effective way to enrich one's vocabulary. I would write down these new words somewhere in order to learn them at a later date. Yet I would easily loose track of all the papers and notes.

That's how I came up with Linguappo. I needed an app to store these words and expressions, so that I could easily review them at home or on my mobile phone in public transports. This would motivate me to train on a regular basis and manage my vocabulary in a more efficient way.

A few years ago, I started to develop an android app (Java) for this language idea. It became the concept behind developing Linguappo, which ended up being a Web Application with a responsive design, developing both Front-end and Back-end, along with a database system and authentification functions. And most of all, it was my first Web Development challenge and product.

How it works

Sign-up and Dashboard

Users must first signup and create an account, which information is saved in the MongoDb database. Then, they will land on the main dashboard, where they can:

Create a new project for a specific language and theme.

Manage and visualize data of a project: number of incomplete and total vocabulary, chronological entries in graphic form.

Directly complete the missing translations.

Vocabulary and Tags

For a specific project, users can save their own items:

Enter some data (word, expression, verb, etc.) and its translation (directly or complete at a later date).

Create as many tags as needed in order to regroup the items, e.g. 'Adjective', 'Verb', 'Expression', 'Slang', etc.

Manage tags: edit or delete them. It will update automatically the database.

Game

The central part of the app. It enables users to:

Filter data according to various information: tags, number of items, sampling method, their evaluation of knowledge.

Play the 'Flipping Card' game in both language directions, validate their knowledge (pass or fail), and get the final score.

Manage the item: delete it or update its information (vocabulary, translation, tags, knowledge evaluation).

Dictionary

Users can search for an item for a specific project. They can:

Look for either the vocabulary and get in return its translation, or vice-versa.

Architecture

MVC(S) Pattern

For the first development version of my Application, I implemented an architecture based on the MVC (Model-View-Controller) pattern. I later refactored it and introduced Services in order to make functions reusable across my various controllers.

Models

My data access layer has 4 models (User, Project, Vocabulary, Tag). Each interacts with the MongoDb database by performing queries to get/save/update specific data.

Views

Single pages and their respective modals are written as ejs templates. In each of them, partials (header, footer, navbar, etc.) are included.

Controllers

They directly use Service classes. As such, I do not need to rewrite the same functions for different controllers. It complies well with the DRY principle.

Services

These contain my business logic. They represent a layer between my controllers and models. There is one Service for one Model.

On the Front-End

While refactoring the code, I implemented various controller closures in order to split my user interfaces from the logic:

  • For instance, the game logic closure has a collection of functions for storing data, calculating game result, etc.
  • On the other hand, the game UI closure keeps track of DOM elements and performs actions such as flip the card, display or hide icons, etc.

I made use of Ajax calls in order to modify only a specific element without forcing the whole html page to reload.

Lessons Learnt

This application still reveals great potential for refactoring some parts of the code.

The design was not fully planned beforehands, so it lacks some consistency in Typography and color scheme

My css code lacks consistency and could be improved by using some CSS pre-compiler.

Refactoring the whole architecture gave me an insight into clean code and the DRY concept. I shall apply these principles in my future apps.

A future challenge would be to create a similar app like this one, this time using React as a front-end library and UI Materials as a UI framework.
